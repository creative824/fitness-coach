# תוכנית טכנית

מקור האמת למוצר הוא מסמך האפיון. הקובץ הזה מתעד איך בונים אותו: סטאק, מבנה תיקיות, סכמת נתונים, מנוע התוכנית והשלבים.

## סטאק

| שכבה | בחירה | הערה |
| --- | --- | --- |
| Frontend | Next.js 16 (App Router) + React 19 + TypeScript | PWA, ללא אפליקציה native |
| UI | Tailwind CSS 4, אייקונים lucide-react, פונט Heebo | RTL מלא, mobile-first |
| DB / Auth / Storage | Supabase (Postgres, Auth, Storage) | RLS על כל טבלה פרטית |
| חיפוש סמנטי | pgvector בתוך Supabase | רק לצ'אט ולהסברים |
| AI | ספק דרך השרת בלבד, מאחורי שכבת `AIProvider` | ברירת המחדל באפיון: OpenAI |
| ולידציה | zod | סכמת התוכנית ב-`src/lib/plan/schema.ts` |
| בדיקות | vitest (לוגיקה), PGlite (סכמה ו-RLS) | `npm test`, `npm run test:db` |
| אירוח | Vercel | סביבות dev / staging / production נפרדות |

## סכמת נתונים

הקובץ `supabase/migrations/0001_init.sql` מגדיר את כל הטבלאות מסעיף 17 באפיון, ועוד שלוש שנדרשות כדי לממש אותו: `recipes` (מאגר מתכונים), `muscles` (מיפוי השרירים לאיור), ו-`wellbeing_logs` (אנרגיה ומצב רוח).

עקרונות הרשאה:

- משתמש קורא וכותב רק את השורות שלו (פרופיל, העדפות, יעדים, יומני משקל ואימון, שיחות).
- תוכניות, משימות, ניקוד והודעות המאמן נכתבים **רק בצד השרת**. המשתמש יכול לקרוא אותם אבל לא לזייף תוכנית או להעניק לעצמו נקודות.
- ניקוד כפול נמנע ברמת המסד: לכל משימה יש לכל היותר שורת השלמה אחת.
- הרשאת אדמין מגיעה מ-`app_metadata.role`, שרק שירות השרת יכול לשנות.
- תרגילים ומתכונים גלויים למשתמשים רק אחרי אישור (`review_status = 'approved'`).
- מקורות הידע וה-embeddings לא נגישים מהדפדפן בכלל.

`npm run test:db` מריץ את המיגרציה ובודק את כל הכללים האלה.

## מנוע התוכנית

ה-AI פועל בשלב אחד בלבד. כל השאר קוד שנבדק:

1. **פרופיל ושאלון**: הנתונים מהשאלון.
2. **בדיקת נתונים ובטיחות** (קוד): ערכים חסרים, יחידות, גיל 18+, דגלי בטיחות. דגל חיובי מעביר למסלול זהיר (תנועה והרגלים בלבד, בלי יעד קלורי) ולהפניה לאיש מקצוע.
3. **חישוב יעדים** (קוד): טווח קלורי (כטווח, לא מספר מדויק), יעד שתייה, נפח אימון שבועי.
4. **סינון מהמאגר** (קוד): תרגילים לפי ציוד, ניסיון ומגבלות; מתכונים לפי אלרגיות, סגנון תזונה וזמן בישול.
5. **AI מרכיב את השבוע**: מקבל רק את המועמדים המסוננים ומחזיר JSON לפי `weeklyPlanSchema`, עם מזהים בלבד והסבר קצר.
6. **בדיקת עקביות** (קוד): סכמה, אלרגנים, ציוד חסר, עומס. כישלון חוזר לשלב 5 לתיקון (מספר ניסיונות מוגבל).
7. **שמירה**: גרסה חדשה ב-`plans`, ומשימות יומיות ב-`daily_tasks`.

מאגר הידע (RAG) משמש את הצ'אט וההסברים עם ייחוס למקור, ולא את בחירת התרגילים.

## החלטות שנלקחו

- **Cache Components פעיל** (ברירת המחדל של Next 16). מסכים שקוראים את הסשן יעטפו ב-`Suspense` בשלב 1.
- **Service worker נדחה לשלב 7**. ב-PWA מספיק manifest כדי להתקין, ו-SW בזמן פיתוח גורם לבעיות cache.
- **סכמת התוכנית מכילה מזהים בלבד** (recipe_id, exercise_id). זה מונע מה-AI להמציא תרגילים, כמויות או ערכים תזונתיים.
- **טבלת `knowledge_sources` משתמשת במזהה טקסט** כדי להתאים למזהה היציב של בוט איסוף המאמרים (sha1 של ה-URL המנורמל).
